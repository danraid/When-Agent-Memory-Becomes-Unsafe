## Scientific boundary and provenance

Six upstream PEP/RFC source-target relationships were already verified by original Git commit and blob hashes in P07b. The new instrument reconstructs the same exact original revisions, extracts **verbatim passages from the superseding documents** by unique anchors and pins their line number, source path, revision, blob SHA-1 and document/excerpt SHA-256. It generates one researcher-written *hypothetical operational request* per source pair, covering:

| Source pair | Research-authored decision scenario | Real-world evidence not provided by a document link alone |
|---|---|---|
| PEP 5 → 387 | Removing Python functionality without a deprecation warning | Actual product version, permitted exception, date of applicability |
| PEP 291 → 387 | Applying old Python 2 compatibility policy to Python 3 library | Applicable Python version and governing accepted process |
| PEP 215 → 292 | Proposing dollar-prefixed string syntax in place of `string.Template` | Actual language-change approval and scope |
| PEP 631 → 621 | Accepting malformed `pyproject.toml` dependency metadata | Build backend version, active published metadata standard |
| Rust RFC 1201 → 2972 | Using forbidden inline attribute or non-assembly body on naked functions | Compiler feature activation and version-specific implementation |
| Rust RFC 1183 → 1974 | Reusing an earlier global allocator interface | Stabilisation/release timeline and runtime compatibility |

**Important:** Documents were authored externally, but these six operational scenarios were created for this study; they are **not observed production incidents**, observational naturalistic decisions, externally administered policy requests or source-independent human cases. A source's public creation date does not prove the effective time of a policy; a commit proves byte identity, not issuer authenticity or authorisation precedence.

The artefact leaves all unknown real-world issuer ranks, observed/effective dates, scope applicability and final decision times as `null`, marks the six records `UNADJUDICATED` and contains **no approve/reject/abstain gold labels**. Separate blank forms are provided as a research intake aid, not as evidence that a person participated. Any evaluation based on those drafts before genuine human review would be a new synthetic/constructed development pilot, not validation of naturally occurring real cases.
