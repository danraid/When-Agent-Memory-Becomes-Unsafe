# Design Doc | WAMBU-001 | initial paper instrument

## Bounded objective and terminal state

Populate the new paper repository with an independent, version-pinned hub copy and an executable article-specific *genuine recursive compaction* instrument. Establish a draft hypothesis, documented estimand, deterministic independent evaluator, separate development/pilot seeds, a closed confirmatory gate, CI checks and an explicit real-provider pilot path. A manuscript result or external submission is out of scope.

## Actual starting evidence

The new paper repository was empty. The generic hub v0.5.0 passed real-provider **technical** homologation (50 decisions plus two advisory reviews), but that generic task did not generate genuinely recursive GPT memory summaries. Those engineering observations do not establish this article's hypothesis. Scientific novelty has not yet been verified against recent literature.

## Authority and validity constraints

No science is frozen yet. `protocol/STUDY_PLAN.json` is a proposed design, not a retrospectively registered result. Only the human author may approve a confirmatory lock. Secrets and confirmatory seeds must never enter prompts or a public commit. No hidden gold action may enter any model call. The independent deterministic evaluator can inspect reference state only after model responses are returned.

## Architecture and trade-offs

Copy the hub as source files under `article_hub/`; add paper-specific logic under `study/`, leaving the generic test instrument unchanged. Use one genuine GPT compactor per episode at steps 3,6,9, etc. The same summary is used by unprotected and ledger-pinned conditions, isolating the explicit ledger as a systems intervention. Reuse the exact pinned-ledger raw model answer for the guard derivative. This avoids extra stochastic model calls and prevents guard correctness being confused with independent GPT skill.

Use a deterministic synthetic workflow with initial policy, authoritatively superseded rules, distractors and mixed transactions. Upstream balances follow an oracle path to keep conditions paired. This does not model state-dependent cascading agent action errors, an explicit limitation.

## Execution packages

1. Versioned copy: manifest and files independently verified.
2. Scientific proposal: candidate literature, primary effect definition and holdout rules.
3. Study instrument: genuine recursive compactor, four decision conditions plus a derived guard and deterministic judging.
4. CI: no API needed, tests reject malformed prompts, duplicate provider IDs and tampered evidence.
5. Pilot: only run where the article's own OpenAI secret is present; require actual provider IDs/usage and a complete evidence package.
6. Decision: technical pilot evidence permits design review, **not** confirmatory release or manuscript claims.

## Acceptance and genuine blockers

PASS if the article imports cleanly, all tests pass remotely and mocks remain labelled fixtures. Real pilot is COMPLETE only when its own provider responses and summary records exist. Missing secret is a genuine external dependency and must be stated as BLOCKED, never silently faked. Any method change after freeze invalidates the lock. Confirmatory testing, publication and authorisation are out of scope.
