**Decision class:** engineering fixes, with prospective scientific choices left for author freeze. **Prior v1 data:** historical development only; not compatible with the v2 source hash and not to be pooled as confirmation.

2. Permuted request modes prevent deterministic time-index shortcuts while maintaining safe/reject opportunity coverage.

6. Confirmatory seed untouched; lock, approval, and submission gates remain closed. Any missing provider/model/evidence dependency is reported as BLOCKED, not silently converted to a success state.

## Alternatives considered

- Replace the ledger condition with equal-information input: would change the question from a systems-level persistence intervention to an intrinsic-memory comparison. **Not selected.** Instead interpret explicitly as unequal-information architecture comparison and log model input tokens.
- Keep the oracle-derived guard: non-deployable answer leakage. **Rejected.** Construct an independently maintained policy ledger by parsing only authenticated public rule events.
- Draw a uniform random set of cases for reviewer prompts: risks missing post-compaction cases. **Rejected.** Use reproducible SHA256 ranking within pre/post-compaction strata, paired across conditions, excluding gold outcomes.
- Randomise every request without coverage: risks episodes with no primary endpoint opportunities. **Rejected.** Shuffle balanced scenario types within each six-step block.
- Apply row-level statistical tests: severe pseudoreplication. **Rejected.** Use independent episode contrasts with prospectively proposed paired tests.
